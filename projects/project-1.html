PROJECT 01.

교내 중고 거래 웹사이트

5인 팀 · Flask·Firebase 기반 교내 중고 거래 웹사이트 개발, 로그인·찜하기 담당. 병합 때 드러난 충돌과 데이터 연결 오류를 팀 작업 기준 통일로 해결.

결과 숫자

  • 01

    2건

    가입~리뷰 흐름 점검으로 찾아 전달한 오류

  • 02

    0건

    최종 시연 오류

개요

기간
약 2개월
인원·역할
5인 팀 / 로그인·찜하기 기능, 작업 규칙 제안, 사용자 흐름 점검
도구
Flask, Firebase, Git

01문제 정의

배경
기능별로는 정상이었지만, 코드를 병합하는 순간 문제가 한꺼번에 드러남
해결하려던 문제
① 같은 파일 동시 수정으로 병합 충돌 반복
② 팀원마다 다른 값으로 상품을 가리켜 찜·리뷰가 엉뚱한 상품에 연결
목표
병합 충돌 없는 기능 통합, 찜·리뷰의 올바른 상품 연결

02데이터와 방법

다룬 데이터
회원·상품·찜·리뷰 데이터 (Firebase)
담당 기능
로그인, 찜하기
사용 도구
Flask, Firebase, Git (테스트 브랜치 → main 브랜치)

핵심 행동과 결과

  • 01

    문제해결

    병합 충돌·찜/리뷰 오연결의 원인을 팀 작업 기준 불일치로 판단

    How + Result공용 파일 수정 순서, "테스트 브랜치 → main" 병합 규칙 제안 → 병합 충돌 해소

  • 02

    데이터 정합성

    팀원마다 다른 값으로 상품을 가리켜 찜·리뷰 오연결 발생

    How + Result상품 식별자 고유 ID로 통일, 규칙 공지 → 찜·리뷰 올바른 상품에 연결

  • 03

    의사소통

    팀원 의견 수렴 후 작업 규칙 합의, 점검 결과 정확히 전달

    How + Result가입~구매·리뷰 흐름 점검, 오류 2건을 재현 순서와 함께 전달 → 최종 시연 오류 0건

04막혔던 부분과 해결 과정

  • 문제 상황

    기능 병합 시 같은 파일 동시 수정으로 충돌 반복, 담당한 찜은 물론 리뷰까지 엉뚱한 상품에 연결

    Point각자 만들 때는 보이지 않던 문제가 병합하는 순간 한꺼번에 드러남

  • 원인

    공용 파일 수정 순서 부재, 팀원마다 다른 상품 지칭 값

    Point팀의 작업 기준 불일치

  • 해결책

    팀원 의견 수렴 → 공용 파일은 정해진 순서로 수정, 테스트 브랜치를 거쳐 main에 병합하도록 제안, 상품 식별자 고유 ID로 통일·공지

    Point병합 충돌 해소, 찜·리뷰 올바른 상품에 연결
