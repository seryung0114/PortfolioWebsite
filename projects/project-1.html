PROJECT 01.

교내 중고 거래 웹사이트

5인 팀으로 Flask·Firebase 기반 교내 중고 거래 웹사이트를 개발함(약 2개월). 로그인·찜하기 기능을 구현하고, 병합 과정에서 발생한 충돌과 찜·리뷰 데이터 오매핑을 팀 작업 기준 통일로 해소함.

결과 숫자

  • 01

    2건

    가입 - 구매 - 리뷰 시나리오 테스트로
    발견해 재현 절차와 함께 공유한 오류

  • 02

    0건

    병합 절차·상품 ID 규칙 통일 후
    최종 시연 오류

기술 스택

01문제 정의

배경
기능별로는 정상 작동했으나 코드 병합 순간 문제 발생
해결하려던 문제
① 같은 파일을 동시에 수정해 병합 충돌 반복
② 팀원마다 다른 값으로 상품을 가리켜 상품 연결 불일치
목표
병합 충돌 없는 기능 통합, 찜·리뷰 데이터의 정확한 상품 매핑

02구현 내용

로그인
사용자 인증 및 로그인 상태 처리 (Flask)
찜하기
특정 상품의 찜 등록 및 해제
Firebase
사용자와 상품 데이터 저장 및 조회
Git 협업
테스트 브랜치에서 기능 검증 후 main 브랜치에 병합

실행 화면

03핵심 문제 해결

사례 1병합 충돌 반복Git 협업

  1. 문제

    동일 파일 동시 수정으로 병합 시 충돌 반복 발생

  2. 원인

    공용 파일 수정 순서 및 브랜치 병합 규칙 부재

  3. 해결

    공용 파일 수정 순서 지정, main 반영 전 테스트 브랜치에서 통합 결과를 먼저 확인하는 병합 절차 도입

  4. 결과

    이후 병합 시 충돌 미발생

사례 2찜·리뷰 데이터 오매핑데이터 정합성

  1. 문제

    찜·리뷰 데이터가 대상이 아닌 다른 상품에 연결

  2. 원인

    팀원별 상품 참조 기준(식별값) 불일치로 데이터 매핑 혼선 발생

  3. 해결

    상품 고유 ID로 식별 기준 통일 및 팀 내 규칙 공유

  4. 결과

    찜·리뷰 데이터의 대상 상품 정상 매핑

04결과·검증

지표별 판단 기준과 결과
지표 판단 기준 전 후
병합 충돌 병합 시 충돌 미발생 충돌 반복 발생 충돌 미발생
찜·리뷰 매핑 대상 상품과 1:1 일치 타 상품으로 오연결 대상 상품 정상 연결
최종 시연 주요 시나리오 오류 없이 통과 테스트 중 오류 2건 확인 오류 0건으로 시연 통과

검증 방법

회원가입부터 구매·리뷰 작성까지 핵심 사용자 시나리오(E2E)를 직접 수행하며 검증함. 발견한 오류 2건은 재현 절차와 함께 공유 후 수정 완료함.
