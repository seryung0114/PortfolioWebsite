PROJECT 01.

교내 중고 거래 웹사이트

5인 팀으로 Flask와 Firebase 기반 교내 중고 거래 웹사이트를 만들며 로그인과 찜하기 기능을 맡았습니다. 병합할 때 드러난 충돌과 데이터 연결 오류를 팀의 작업 기준을 통일해 해결했습니다.

결과 숫자

  • 01

    2건

    가입~리뷰 흐름 점검으로 찾아 전달한 오류

  • 02

    0건

    최종 시연 오류

개요

기간
약 2개월
인원·역할
5인 팀 / 로그인·찜하기 기능, 작업 규칙 제안, 사용자 흐름 점검
도구
Flask, Firebase, Git

01문제 정의

배경
각자 기능을 만들 때는 보이지 않던 문제가 코드를 병합하는 순간 한꺼번에 드러났습니다.
해결하려던 문제
① 모두가 같은 파일을 동시에 고쳐 병합할 때마다 충돌이 반복됐습니다.
② 팀원마다 상품을 다른 값으로 가리켜, 찜과 리뷰가 엉뚱한 상품에 연결됐습니다.
목표
병합 충돌 없이 기능을 합치고, 찜과 리뷰가 올바른 상품에 연결되도록 하기

02데이터와 방법

다룬 데이터
회원·상품·찜·리뷰 데이터 (Firebase)
담당 기능
로그인, 찜하기
사용 도구
Flask, Firebase, Git (테스트 브랜치 → main 브랜치)

해결 흐름

  1. 1 원인 판단 충돌과 잘못된 연결의 원인을 팀의 작업 기준 불일치로 판단
  2. 2 작업 규칙 제안 공용 파일은 정해진 순서로 수정, 테스트 브랜치를 거쳐 main에 병합
  3. 3 식별자 통일 상품을 고유 ID로 가리키도록 통일하고 규칙 공지
  4. 4 사용자 흐름 점검 가입부터 구매·리뷰까지 따라가며 오류 2건을 재현 순서와 함께 전달

04막혔던 부분과 해결 과정

막힌 상황
각자 만든 기능을 합치자 같은 파일을 동시에 고친 탓에 병합 충돌이 반복됐고, 제가 맡은 찜은 물론 리뷰까지 엉뚱한 상품에 연결됐습니다.
원인
팀의 작업 기준이 통일되지 않았습니다. 공용 파일을 고치는 순서가 없었고, 팀원마다 상품을 다른 값으로 가리켰습니다.
해결 방법
팀원들의 의견을 모아 각자 작업은 그대로 하되 공용 파일은 정해진 순서대로 고치고, 테스트 브랜치를 거친 뒤 main 브랜치에 병합하도록 제안했습니다. 상품 식별자도 고유 ID로 통일해 규칙을 공지했습니다.
결과
이후 병합 충돌이 사라졌고 찜과 리뷰도 올바른 상품에 연결됐습니다.
