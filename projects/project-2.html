PROJECT 02.

화장품 매장 판매 분석 시스템

6인 팀으로 Java·MySQL 기반 화장품 매장 판매 분석 시스템을 개발함(약 3주). 제품별 매출, 고객층(연령대·피부 타입)별 구매 패턴, 가격 변동이 판매량과 매출에 미치는 영향 추적을 목표로 함. 고객 이력 테이블 설계와 입력·조회 기능을 담당함.

결과 숫자

    과거 매출을 주문 당시 기준으로 집계

  • 02

    검증 + 롤백

    잘못된 데이터와
    일부만 저장되는 데이터 차단

01문제 정의

분석 목표
제품별 매출, 고객층(연령대·피부 타입)별 구매 패턴, 가격 변동이 판매량과 매출에 미치는 영향 추적
해결하려던 문제
가격·고객 정보(연령대·피부 타입) 변경 시 지난 주문까지 새 값으로 집계되어 변화 전후 비교 불가
설계 목표
주문 당시 가격·고객 상태 보존, 잘못되거나 일부만 저장된 데이터 차단

02구현 내용

고객 이력 테이블
고객 정보(연령대·피부 타입 등) 변경 시 유효 기간과 함께 이력으로 저장 (MySQL)
주문 단가
주문 시점의 단가를 주문 데이터의 별도 칼럼에 저장
당시 기준 집계
주문일과 고객 이력의 유효 기간을 맞춰 당시 상태 기준으로 매출 집계 (SQL)
입력·저장
PreparedStatement 바인딩, 저장 전 필수값·고객/상품 존재·중복 검증, 오류 시 트랜잭션 롤백 (Java)

데이터베이스 구조

SQL 쿼리 예시

03핵심 문제 해결

사례 1가격·고객 정보 변경 시 과거 매출 왜곡거래 데이터 이력 관리

  1. 문제

    가격·고객 정보 변경 시 지난 매출까지 새 값으로 재계산되어 가격 변동·고객층별 분석 왜곡 우려

  2. 원인

    현재 값만 참조하는 구조로 주문 당시 가격·고객 상태 미보존

  3. 해결

    주문 시점 단가 별도 칼럼 저장, 고객 이력에 유효 기간을 두어 주문일 기준 당시 상태 조회

  4. 결과

    가격 변경 후에도 과거 매출의 주문 당시 기준 집계 확인

사례 2잘못된 데이터와 일부만 저장된 데이터데이터 무결성

  1. 문제

    필수값 누락·없는 고객/상품·중복 상품 저장, 저장 중 오류 시 일부 데이터만 남을 위험

  2. 원인

    저장 전 검증 부재 시 잘못된 값 유입, 여러 단계로 나뉜 저장 중 오류 시 일부만 반영

  3. 해결

    저장 전 입력값 검증, PreparedStatement 값 바인딩, 저장 중 오류 시 트랜잭션 롤백

  4. 결과

    잘못된 데이터와 일부만 저장된 데이터 차단

04결과·검증

지표별 판단 기준과 결과
지표 판단 기준 결과
과거 매출 집계 가격 변경 후에도 주문 당시 단가·고객 상태로 집계 주문 당시 기준 집계 확인
잘못된 입력 누락·중복 값 입력 시 저장 차단 저장 차단 확인

검증 방법

가격 변경 후 과거 매출을 다시 조회해 주문 당시 기준 집계 여부를 확인함. 누락·중복 값을 직접 입력해 저장 차단 여부를 확인함.
