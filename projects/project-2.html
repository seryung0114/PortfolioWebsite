PROJECT 02.

화장품 매장 판매 분석 시스템

6인 팀으로 Java·MySQL 기반 화장품 매장 판매 분석 시스템을 개발함(약 3주). 제품별 매출, 고객층(연령대·피부 타입)별 구매 패턴, 가격 변동이 판매량과 매출에 미치는 영향을 추적하는 것이 목표였음. 고객 이력 테이블 설계와 입력·조회 기능을 맡음.

결과 숫자

  • 01

    당시 기준 집계

    과거 매출을 주문 당시 기준으로 집계

  • 02

    검증 + 롤백

    잘못된 데이터와
    일부만 저장되는 데이터 차단

01문제 정의

분석 목표
제품별 매출, 고객층(연령대·피부 타입)별 구매 패턴, 가격 변동이 판매량과 매출에 미치는 영향 추적
해결하려던 문제
가격이나 고객 연령대·피부 타입이 바뀌면 지난 주문까지 새 값으로 집계되어 변화 전후를 비교할 수 없음
설계 목표
주문 당시의 가격과 고객 상태를 보존하고, 잘못되거나 일부만 저장된 데이터가 남지 않게 함

02구현 내용

고객 이력 테이블
고객 정보(연령대·피부 타입 등)가 바뀔 때마다 유효 기간과 함께 이력으로 저장 (MySQL)
주문 단가
주문 시점의 단가를 주문 데이터의 별도 칼럼에 저장
당시 기준 집계
주문일과 고객 이력의 유효 기간을 맞춰 당시 상태 기준으로 매출 집계 (SQL)
입력·저장
PreparedStatement 바인딩, 저장 전 필수값·고객/상품 존재·중복 검증, 오류 시 트랜잭션 롤백 (Java)

데이터베이스 구조

SQL 쿼리 예시

03핵심 문제 해결

사례 1가격·고객 정보 변경 시 과거 매출 왜곡거래 데이터 이력 관리

  1. 문제

    가격이나 고객 연령대·피부 타입이 바뀌면 지난 매출까지 새 값으로 다시 계산되어, 가격 변동·고객층별 분석 결과가 왜곡될 수 있었음

  2. 해결

    주문 시점 단가를 별도 칼럼에 저장하고, 고객 이력에 유효 기간을 두어 주문일 기준으로 당시 상태를 조회함

  3. 결과

    가격 변경 후에도 과거 매출이 주문 당시 기준으로 집계되는 것을 확인함

사례 2잘못된 데이터와 일부만 저장된 데이터데이터 무결성

  1. 문제

    필수값 누락, 없는 고객·상품, 중복 상품이 저장되거나 저장 중 오류로 일부 데이터만 남을 수 있었음

  2. 해결

    저장 전에 입력값을 검증하고 PreparedStatement로 값을 바인딩함. 저장 중 오류가 나면 트랜잭션을 롤백함

  3. 결과

    잘못된 데이터와 일부만 저장된 데이터가 남지 않도록 막음

04결과·검증

이력 보존 확인
가격을 바꾼 뒤 과거 매출을 다시 조회해 주문 당시 기준으로 집계되는지 확인함
입력 검증 확인
누락·중복 값을 넣어 저장이 차단되는지 확인함

05AI 도구 활용

활용 도구

검증 과정

직접 수행
고객 이력 테이블 설계, 입력값 검증 로직 작성, 저장 로직을 트랜잭션으로 묶어 오류 시 롤백되도록 수정

06배운 점

배운 점
은행 거래 기록처럼 거래 당시의 가격과 고객 상태가 그대로 남아야 분석 결과를 믿을 수 있다는 점을 배움
다시 한다면
가격·고객 정보 변경 상황을 테스트 케이스로 정리해 반복 검증하고, 이력 유효 기간 규칙을 팀 공통 문서로 먼저 정리하겠음
