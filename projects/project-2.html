PROJECT 02.

화장품 매장 판매 분석 시스템

6인 팀으로 Java와 MySQL 기반의 화장품 매장 판매 분석 시스템을 만들며 고객 이력 테이블 설계와 입력·조회 기능을 맡았습니다. 가격이나 고객 정보가 바뀌어도 과거 매출이 주문 당시 기준으로 집계되도록 설계했습니다.

핵심 결과

  • 01

    주문 당시 기준

    가격이 바뀐 뒤에도 과거 매출 집계

  • 02

    검증 + 롤백

    누락·중복 데이터와 일부만 저장되는 일 방지

개요

기간
약 3주
인원·역할
6인 팀 / 고객 이력 테이블 설계, 입력·조회 기능
도구
Java, MySQL

01문제 정의

배경
매장의 가격과 고객 정보는 시간이 지나면서 바뀝니다.
해결하려던 문제
정보가 바뀌었다고 지난 매출까지 새 값으로 다시 계산되면 분석 결과를 믿을 수 없습니다.
목표
과거 매출은 주문 당시 기준으로 집계하고, 잘못되거나 일부만 저장된 데이터가 남지 않게 하기

02데이터와 방법

다룬 데이터
고객 이력·상품·주문 데이터 (MySQL)
담당 기능
고객 이력 테이블 설계, 입력·조회 기능
사용 도구
Java, MySQL (PreparedStatement, 트랜잭션)

처리 흐름

  1. 1 당시 단가 저장 주문 시점의 단가를 별도 칼럼에 저장
  2. 2 당시 상태로 조회 주문일을 고객 이력의 유효 기간과 맞춰 당시 상태로 집계
  3. 3 저장 전 검증 필수값 누락, 없는 고객·상품, 중복 상품을 걸러내고 PreparedStatement로 SQL 인젝션 방지
  4. 4 오류 시 롤백 저장 중 오류가 나면 트랜잭션을 롤백해 일부만 저장되지 않게 함

03결과

항목별 판단 기준과 결과
항목 판단 기준 결과
과거 매출 집계 가격이 바뀐 뒤에도 주문 당시 단가로 집계 주문 당시 기준으로 집계되는 것 확인
잘못된 입력 필수값 누락·없는 고객/상품·중복 상품은 저장하지 않음 저장 전에 걸러냄
저장 중 오류 일부 데이터만 저장되지 않음 트랜잭션 롤백
확인 방법
가격을 바꾼 뒤 과거 매출을 다시 조회해, 주문 당시 기준으로 집계되는지 확인했습니다.

04막혔던 부분과 해결 과정

문제 상황
가격이나 고객 정보가 바뀌면 지난 매출까지 새 값으로 다시 계산되어, 분석 결과를 믿을 수 없게 될 수 있었습니다.
해결 방법
주문 시점의 단가를 별도 칼럼에 저장하고, 조회 기능에서는 주문일을 고객 이력의 유효 기간과 맞춰 당시 상태로 집계했습니다.
데이터 보호
입력값은 PreparedStatement로 바인딩해 SQL 인젝션을 막고, 필수값 누락과 없는 고객·상품, 중복 상품은 저장 전에 걸러냈습니다. 저장 중 오류가 나면 트랜잭션을 롤백했습니다.
결과
가격 변경 후에도 과거 매출이 주문 당시 기준으로 집계되는 것을 확인했습니다.
